# Schedule verification ledger

**Repository source-review cutoff:** `2026-08-22`

For rows marked **Primary** or **Partial**, the modeled current normal-week
schedule was compared with operator or regulator primary material through the
cutoff above and is source-verified within the row's stated scope. This is a
backward-looking review date, not an expiry date or a promise about future
exchange changes. **Known issue**, **Secondary**, and **Pragmatic** rows are
explicitly excluded from that verified set. `Unknown` and other **Synthetic**
profiles are library policy, not exchange facts. The quantified result and
method are in the [2026-08-22 audit report](audit-2026-08-22.md).

Every non-synthetic `Exchange` row was reviewed through at least `2026-08-22`. A later review
should change only the affected rows until all non-synthetic rows have caught
up; the repository cutoff advances only when the complete ledger has been reviewed. Exact
historical notices and effective-date evidence remain beside the owner code.
The source-set links below are the stable places from which the next review
starts; see [sources.md](sources.md) and the repeatable
[update workflow](updating.md).

## Basis

- **Primary** — current boundaries are supported by an exchange, operator, or
  regulator source, with no known modeled-history gap since January 2010.
- **Partial** — current boundaries have primary support, but a modeled
  historical era, phase, or exact cutover has a documented gap.
- **Secondary** — the captured schedule relies on corroborating material rather
  than a primary source.
- **Pragmatic** — the profile is an intentionally representative
  exchange/product-family default, not a venue-wide claim.
- **Known issue** — current primary material conflicts with, supersedes, or no
  longer identifies the modeled venue/profile; reconcile before relying on it.
- **Synthetic** — deterministic library policy with no real exchange schedule.

These are canonical `snake_case` serde names. They are reusable product-family
profile keys, not additional exchanges. Their current-schedule review state

represent. The fixed snapshot APIs remain available; the dated key API and
`calendar_for_market_hours_key` reuse the corresponding sourced revisions.
Names are stable wire identities. This crate does not map product symbols to
keys, and venue defaults must not be substituted for a different family.
