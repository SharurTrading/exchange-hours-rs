# Working tools for the stage-2.2 CME holiday waves.
#
# These are not part of the crate; they reproduce the committed holiday rows
# from the research store's evidence blocks, and each wave's checker re-derives
# every value it can from the raw artifacts. The committed tables, evidence
# files and tests are the product; these scripts are how they were built.
#
# ## Wave 4 — the 2019-2021 era (issue #91)
#
#   python3 tools/wave4_repair.py       # repair the block -> tools/out/repair/*
#   python3 tools/wave4_rows.py         # repaired block + raw indexes -> tools/out/wave4/*
#   python3 tools/check_wave4.py        # re-derives every wave-4 row and venue table
#   python3 tools/encode_wave4.py . tools/out/wave4/ROWS.json   # plan -> the eight modules
#   python3 tools/venue_intersection_wave4.py --check           # D17 venue tables
#   python3 tools/evidence_wave4.py     # modules + tools/out/wave4 -> docs/evidence/*
#
# **`WAVE4_RESEARCH` is required** by `wave4_repair.py`, `wave4_rows.py` and
# `check_wave4.py`, and must name the research store's root — the directory
# holding `holidays/cme-2019-2021.r2.json` and `holidays/raw/`. That store is
# deliberately not committed, so there is no default that would work on another
# machine; each script exits with a message if it is unset.
#
#   WAVE4_RESEARCH=../exchange-hours-research python3 tools/wave4_rows.py
#
# `wave4_repair.py` is new to this wave: `cme-2019-2021` is the one block the
# verifier failed on evidence discipline alone, so its 314 truncated
# `verbatim`/instant fields were re-emitted at full length from the saved bytes,
# and the two `INDEX.md` files and `shasum.txt` preamble were corrected, before
# any row or evidence file was written from it.
#
# ## Wave 3 — the 2022-2024 era (issue #90), kept so those rows stay reproducible
#
#   python3 tools/wave3_rows.py         # block + raw indexes -> tools/out/*
#   python3 tools/check_wave3.py        # re-runs the wave-3 generator and re-checks it
#   python3 tools/encode_rows.py        # tools/out/ROWS.json -> the eight modules
#   python3 tools/venue_intersection.py # the D17 venue tables for any era
#
# **`WAVE3_RESEARCH` is required** by `wave3_rows.py` and `check_wave3.py`, and
# must name the research store's root — the directory holding
# `holidays/cme-2022-2024.r2.json` and `holidays/raw/`:
#
#   WAVE3_RESEARCH=../exchange-hours-research python3 tools/check_wave3.py
#
# `tools/venue_intersection.py` is the wave-3 copy of the venue tool and reads
# only the crate's own modules, so it needs no research variable; the wave-4
# copy differs only in its default era and in where it inserts rows.
#
# `tools/out/` is scratch: it is regenerated by the first command of either wave
# and is not committed, because every value that matters lives in the modules
# and in `docs/evidence/`.
